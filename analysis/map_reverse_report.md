# Reverse-engineering структурной карты оригинального `Fold` (2007)

## 1. Метод и источники

Разбор выполнен по распакованному образу `analysis/memory/unpacked_image.bin`
(база `0x400000`). Основой послужил `analysis/callgraph_report.txt`, но его
аннотации `dbl=` **нельзя использовать для FPU-операндов `dword ptr`**: скрипт
читает 8 байт как `double` и, например, для `0x467424` (`180.0f`) печатает
`dbl=2.000000501`. Все константы ниже перепроверены `analysis/dump_consts.py`
как `f32`, `f64` и `80-bit extended`.

Ключевые helper'ы (подтверждено дизассемблером):

| Адрес | Назначение |
|------|------------|
| `0x40292C` | `fcos` (Delphi `System.cos`) |
| `0x402954` | `fsin` (Delphi `System.sin`) |
| `0x402970` | Delphi `Round`: `fnstcw; or CW,0x0F00; fistp qword; fldcw` → **RC=11, усечение к нулю**, результат `int64` |
| `0x406B54` | `RGB(R=AL, G=DL, B=CL)` → `COLORREF` |
| `0x466198` | карта → экран |
| `0x4661F0` | экран → карта |
| `0x466250` | `H(x,y,θ)` — значение отражающего горизонта |
| `0x46641C` | построение/отрисовка структурной карты |
| `0x466980` | построение временного разреза по нарисованному профилю |
| `0x465BD4` | инициализация массива 300×301 отсчётов |
| `0x465D68` | отрисовка сейсмического разреза (wiggle trace) |
| `0x4674AC` | чтение `integer` из `TEdit` с clamp `[EDX..ECX]` |
| `0x467540` | чтение `float` из `TEdit` с clamp `[0.1..10]` |

## 4. Точная формула `0x466250`

Вход: `EAX = &struct { f32 x; f32 y }`, стек `[ebp+8] = f32 θ` (радианы).
Выход: `f32 H` в метрах.

```
ct = cos(θ); st = sin(θ)                 // 0x40292C / 0x402954
xr = Round(ct*x) - Round(st*y)           // Round = trunc toward zero
yr = Round(st*x) + Round(ct*y)
xc = Round(ct*8000) - Round(st*4000)     // 0x46AE48 / 0x46AE4C
yc = Round(st*8000) + Round(ct*4000)
dx = xr - xc/2;  dy = yr - yc/2
d  = sqrt(|0.4*dx*dx + 0.6*dy*dy|)       // 0x4663E8 / 0x4663F4
q  = d / (26 * sqrt(|dx-210| + 3.4*d))   // 0x466400, 0x466404, 0x466410
H  = 2000 + 250*q                        // 0x466418 / 0x466414
```

Все промежуточные `fstp dword` → `f32`; `ext80`-константы означают, что
вычисления идут в 80-битной точности FPU, но результат каждого шага хранится
в `f32`.

**Confidence: high** — каждый операнд проверен по raw-байтам (`tmp_66250.txt`,
`tmp_6635c.txt`), константы перепроверены decoder'ом.

## 5. Построение карты `0x46641C`

```
N  = Round(step*100) + 1                 // step из 0x46cc5c; Round=trunc
θ  = (angle_minus_90 / 180) * π           // EDX = 0x46cc2c
// проход 1: поиск min/max
H0 = H(0,0,θ); min = max = H0
for i in 1..=N:
    x = (i-1)*8000/N
    ny = (N*Image2.Height) div Image2.Width
    for j in 1..=ny:
        y = (j-1)*4000/ny
        v = H(x,y,θ); min = min(v,min); max = max(v,max)
// проход 2: 21 полоса, цвет и заливка прямоугольника
for i,j:  v = H(x,y,θ)
    for k in 0..=20:
        c = min + k*(max-min)/21
        if |v-c| <= (max-min)/42:
            color = gradient(k/21)       // 0x406B54
            fill_rect(screen(x,y), half = 10/step)  // 0x466978=10, 0x46697C=2
```

`gradient(t)`: `t≤0.25` → `(65, 65+560t, 205)`;
`0.25<t≤0.5` → `(65, 205, 205−560(t−0.25))`;
`0.5<t≤0.75` → `(65+560(t−0.5), 205, 65)`;
`0.75<t≤1` → `(205, 205−560(t−0.75), 65)`.

**Вывод:** структурная карта — **детерминированная аналитическая поверхность**
`H(x,y,θ)`. Пики, качество и скорость в расчёт карты **не входят**.

**Confidence: high** — циклы, границы, константы и вызовы `0x466250` видны
непосредственно в `0x46641C` (строки 1520–1935 `callgraph_report.txt`).

## 6. Временной разрез `0x466980` (для полноты call graph)

```
P1 = screen_to_map(ECX=current_point, 0x46cc44)   // 0x4661F0
P2 = screen_to_map([ebp+0x24]=0x46cc54, 0x46cc44)
len = sqrt((P2.x-P1.x)^2 + (P2.y-P1.y)^2)
n = Round(len/200) + 1                            // 0x46742C
// концы: t = 2*H/V; V = [ebp+0x18] = 0x46cc30
min_out = max_out = 2*H(P1,θ)/V
for s in 0..n:
    шаг = 200 м по dx/dy (0x46742C)
    t = 2*H(point,θ)/V
    min/max обновляются
    заполняется массив 0x7535 dword → 0x465D68
```

Здесь `θ = ([ebp+0x1c]=0x46cc2c)*π/180`, тот же угол, что и в карте.
`2.0f` — `0x467428`. Это подтверждает физику: `H = V·t/2`; в текущем Rust
`time_to_depth` в этом смысле корректна.

**Confidence: high** для формулы `t=2H/V`; medium для деталей отрисовки
(не влияют на карту).

## 7. Оценка текущей реализации Rust

| Файл | Что не так |
|------|-----------|
| `src/grid.rs` | `quality_weight()`使用 `0.4/0.6` как веса качества — неверно: это коэффициенты эллиптического расстояния в `0x466250`. |
| `src/grid.rs` | Радиус `2000 м` (`0x466418`) ошибочно воспринят как радиус отсечения; на самом деле это **база глубины** `+2000`. |
| `src/grid.rs` | Интерполяция пиков и гауссово ядро `1/(1+r²/40000)` в оригинале отсутствуют. |
| `src/grid.rs` | `step=200` использовался как шаг профиля; в оригинале это шаг временного разреза (`0x46742C`), а сетка карты задаётся другим параметром `N`. |
| `src/velocity.rs` | `H = V·t/2` совпадает с оригинальным `t = 2H/V`; требуется только уточнить комментарий. |

## 8. Рекомендуемая замена (реализовано)

1. `horizon_depth(x, y, theta_rad)` — дословная формула из §4 с
   `delphi_round(v) = v.trunc() as i64 as f32` (RC=11 из `0x402970`).
2. Угол: `azimuth_rad = profiles.first().map(|p| p.azimuth()).unwrap_or(0.0)`;
   `azimuth_deg = azimuth_rad.to_degrees()`; `θ = (azimuth_deg−90)·π/180`.
   Явный перевод в градусы обязателен: `azimuth()` возвращает радианы.
3. Внутреннее число узлов original: `N = trunc(step·100)+1`, `ny = N·4000/8000`.
   Публичная сетка остаётся `settings.width × settings.height` (текущий
   рендер/PGM не меняются); узел `(gx,gy)` отображается в original-узел
   `i = 1+trunc(gx·(N−1)/(w−1))`, `j = 1+trunc(gy·(ny−1)/(h−1))`, затем
   `x=(i−1)·8000/N`, `y=(j−1)·4000/ny`. При `step=200` это даёт те же
   координаты узлов, что и прямое `gx·200`, `gy·200`.
4. `quality` в расчёт не включается. `velocity` в расчёт карты не включается
   (используется только при переводе H→t для временного разреза).

**Общий confidence: high** по алгоритму. Позже в `Settings` добавлен явный угол
`angle` (Edit4 = 0) — он и является источником θ, азимут профиля больше не
используется.

### 9.1. Виггл-трассы и таблица корреляции (дополнительный разбор)

Пиксельный разбор разреза (x=180..880, y=456..630) показал, что original
рисует не тонкую синусоиду, а **залитые чёрные лепестки**:

| Признак | Замер |
|---------|-------|
| Оси трасс | x=244, 308, 372, 435, 498, 562, 626, 689, 753, 817 (шаг 63.6 px) |
| Главный лепесток | у x=562 занимает x=563..583 (20 px), y=501..519 (19 px) |
| Боковой лепесток | x=547..562, y=531..553, уже и светлее |
| Цвет заливки | ~(15,15,15), почти чёрный |

Это классический Ricker-вейвлет: `w(t)=(1−2π²f²Δt²)·exp(−π²f²Δt²)`,
`f≈18 Гц` даёт главный лепесток ≈22 px при масштабе 0.4 с / 174 px.
В `src/gui.rs` лепестки заливаются полосками по 1 px с тонким чёрным контуром
поверх — без артефактов невыпуклого полигона.

Таблица корреляции (левая панель) по пикселям:
- рамка StringGrid1: x=34..150, верх y=328;
- шаг строки 12 px, текст начинается x≈38, шрифт ~9 px;
- справа у каждой строки — крестик удаления (реализован в GUI).

## 10. Точная раскладка из бинарного DFM (реверс кода, а не скриншота)

Старый `parse_dfm.py` терял числовые значения (`return None` для типов 2/3/4),
поэтому координаты контролов были «потеряны» и приходилось догадываться по
скриншоту. Новый `analysis/dfm_values.py` парсит DFM `10__TFORM1__0.bin`
полностью (18430 байт, `pos == len(d)`). Результат — `analysis/dfm_values.txt`.

## 11. Уточнения по полям и сетке (final pass)

- `Edit2 = 1500` (V ср), `Edit1 = 3` (качество/шаг сетки), `Edit3 = 95` (f).
  Ранее GUI подставлял 1200/95/10 «от скриншота» — это было не из DFM.
- `0x467540` читает `Edit1` как float и ограничивает его `0.1..10`.
  Поэтому `N = trunc(q·100)+1` (по умолчанию 301), `ny = N·201/800 = 75`.
  Текстура GUI теперь строится в этом внутреннем размере, а не 41×21.
- `0x46641C` сравнивает значение с центрами 21 полосы, то есть индекс
  полосы — `round(u·21)`, цвет строго по формуле градиента из §5.
- `0x466980` задаёт вертикальный масштаб разреза через `t = 2H/V` на
  отсчётах профиля с шагом 200 м; в GUI это `profile_time_bounds()`.
- Label9 в DFM имеет `fsBold + fsUnderline`; подпись Rust рисуется с
  подчёркиванием и остаётся прижатой к правому краю.
