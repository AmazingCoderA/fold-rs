# Fold — Rust-порт программы 2007 года

[![Build](https://github.com/AmazingCoderA/fold-rs/actions/workflows/build.yml/badge.svg)](https://github.com/AmazingCoderA/fold-rs/actions/workflows/build.yml)

Полный независимый порт программы **Fold — «Построение структурной карты отражающего горизонта»** (Viktor Romanov, 2007), написанной на Delphi/VCL и упакованной ASPack.

**Цель:** один в один повторить интерфейс и логику, но считать быстрее оригинала и работать там, где его нет: Windows, Linux, macOS, Android.

### Раскладка восстановлена из DFM оригинала

Координаты **не сняты со скриншота на глаз**: бинарный ресурс `TFORM1`
(original `03_Fold.exe`) даёт точные `Left/Top/Width/Height`, цвета `clXxx`
и размеры шрифтов. Разобрать их было нельзя старым парсером — он выбрасывал
числовые значения типов 2/3/4; новый `analysis/dfm_values.py` сохраняет их.

Ключевое открытие: единственный разрешённый скриншот 894×656 — это окно
оригинала, уменьшенное **ровно на 7/8**. Настоящий клиент формы:
`ClientWidth=1016`, `ClientHeight=694`. Проверка по контролам:

| DFM-контрол | Координаты DFM | На скриншоте (×0.875 + 5 / +47) |

(для контролов внутри `Panel1` в таблице указаны абсолютные координаты —
DFM-значения + смещение панели `(4,40)`)
|-------------|----------------|----------------------------------|
| Image1 (карта) | 200,40 800×400 | 180,82 700×350 |
| Image2 (разрез) | 200,468 800×201 | 180,456 700×176 |
| Image3 (легенда) | 496,444 245×21 | 439,436 214×18 |
| Label3/Label4 | 456,448 / 748,448 | 404,439 / 659,439 |
| Label16 «трассы» | 960,452 | 845,442 |

Поэтому GUI рисуется в **координатах DFM**, а окно можно растягивать:
при ресайзе используется один масштаб на обе оси, поэтому линии не кривятся,
а нижняя подпись остаётся видимой. Раньше код масштабировал всё через
независимые `sx/sy` — отсюда были «кривота», размытые линии и съехавшие
подписи (например, `Y, м` стояла слева, хотя в DFM она справа, x=900).

- шрифты `Arial` / `Symbol` грузятся из `C:\Windows\Fonts` с точными
  начертаниями из DFM: bold 13 для заголовков, bold-italic 15 для шапки,
  Symbol 16 для `f`, bold 11 для `H min`/`H max`, maroon bold+underline
  для подписи внизу;
- левая панель `Panel1` (4,40,173×629, `bsSingle`, `clWhite`) содержит
  `Параметры структуры` (clGreen), `V ср`, `f`, `Координаты профиля` (clNavy),
  `Профиль №` (clMaroon), `Таблица корреляции` (clPurple), `Качество изображения`;
- `StringGrid1` — редактируемая сетка 2×4 (`DefaultColWidth=60`, `RowHeight=24`,
  `FixedRows=0`, неявный `FixedCols=1` ⇒ `FixedColor=clMoneyGreen` в первом
  столбце, `goEditing`): четыре параметра `x0,y0,x1,y1`
  вводятся кликом/дабл-кликом или Tab/Enter и сразу попадают в профиль;
  `Memo1` (125×305, `ssVertical`) — список пиков, у каждой строки крестик
  **×** на этой же строке удаляет только её;
- палитра карты и легенды — одна 21-полосная шкала, **Цвет** переключает
  5 палитр: Классика (original), Океан, Пламя, Лайм, Графит;
- поля ввода имеют утопленную VCL-обводку и синий фокус. **Tab / Shift+Tab**
  обходит V ср → 4 ячейки координат → Качество → f → Memo1 → X → Y (TabOrder
  из DFM); Enter сохраняет ячейку и переводит фокус дальше. Событие клавиши
  удаляется из ввода, чтобы фокус не прыгал дважды. Горячие клавиши меню
  F2/F3/F4/Del/Alt+Del работают как одноимённые кнопки;
- **Структура** — «О программе», **Профили** — Назад/Далее/Ввести вручную/
  Удалить все/Cтереть таблицу, **Строка** — экспорт/импорт строки, **Справка** — помощь;
- сетка: карта 8 вертикальных × 10 горизонтальных делений (шаг 100 и 40 px
  в DFM). Разрез рисуется по `0x465D68`: число трасс равно `trunc(len/200)+1`
  (до 100), шаг `Width/(n+1)`, 10 горизонтальных линий. В original отсчёты
  трасс — 300 на трассу с нормальным шумом (Box–Muller, σ=0.006, LCG
  `0x402BC8`), RMS-нормировкой и амплитудой `0.12/rms·sample·шаг`; в текущей
  версии визуализация упрощена до огибающих по `t=2H/V`, но геометрия трасс,
  время и масштаб уже точно по дизассемблеру;
- пересчёт текстуры только при смене угла/качества/палитры: карта не пересчитывается
  при вводе скорости и пиков. Внутренняя сетка повторяет `0x46641C`:
  `N=trunc(quality·100)+1` (по умолчанию 301×150 узлов), 21 полоса выбирается
  ближайшей к `min+k·span/21`. Растеризация дословно повторяет `Canvas.FillRect`
  оригинала: прямоугольники `10/quality` px в буфере Image1 800×400, порядок
  i(X)→j(Y), поздние заливают ранние. Текстура без интерполяции — жёсткие
  границы как в original;
- линии сетки карты — `clGray ($808080)`, 1 px в координатах DFM, как в
  `0x46641C`;
- вертикальный масштаб разреза берётся из `0x466980`: по активному профилю
  шагают по 200 м и считают `t=2H/V−shift` (сдвиг 0.004 или 0.04 зависит от
  наклона), затем original расширяет диапазон (`min−=0.02`, `max+=0.084`),
  поэтому Edit2 (V ср) реально влияет на подписи времени и положение пиков;
- сам разрез теперь дословно повторяет `0x465BD4`/`0x465D68`: 300 отсчётов на
  трассу, импульс `exp(−2.4|d|/0.05)·sin(2πd/0.05)`, RMS только по первой
  трассе и чёрные горизонтальные отрезки с диагональными стыками отрицательных
  лепестков. Буфер 800×201 кэшируется в текстуру с `NEAREST`, поэтому на каждом
  кадре рисуется один квад, а не тысячи линий;
- клик по разрезу ставит пик, как в `0x468780`: время растёт сверху вниз
  (`t=t_min+Y/H·(t_max−t_min)`), маркер — со сдвигом `(X−6,Y−6)`. Ранее ось
  была перевёрнута, из-за чего пик «прилипал» не к тому месту;
- профиль на карте и клик мышью используют точное преобразование
  `0x466198`/`0x4661F0`: `(W−1)/(H−1)` с вертикальным отражением — линия
  профиля совпадает с текстурой, а не «отражается» относительно неё;
- готовые строки данных проходят те же клампы, что и поля original
  (V 1000..7000, качество 0.1..9.99, угол 0..360), дробные значения не
  округляются при импорте.

## Сборка и запуск

### Desktop

```powershell
cargo build --release
.\target\release\fold.exe examples\demo.txt map.pgm   # CLI
.\target\release\fold-gui.exe                         # GUI
.\target\release\fold.exe --bench                     # бенчмарк
cargo test --release
```

На Linux для GUI нужны:
```bash
sudo apt install pkg-config libx11-dev libxi-dev libgl1-mesa-dev libudev-dev libxkbcommon-dev libwayland-dev
cargo build --release
```

### Android

Нативный код считает карту, Kotlin-интерфейс рисует её и обрабатывает касания:

```bash
cargo install cargo-ndk
cargo ndk --manifest-path android-rs/Cargo.toml \
  -t arm64-v8a -t armeabi-v7a -t x86_64 \
  -o android/app/src/main/jniLibs build --release
gradle -p android assembleDebug
```

APK появится в `android/app/build/outputs/apk/debug/`. В CI это делает job `android`; готовый `fold-android-universal.apk` прикрепляется к каждому релизу вместе с `SHA256SUMS.txt`.

### AUR (Arch Linux)

```bash
yay -S fold-rs-git
# или локально:
cd packaging/aur && makepkg -si
```

Инструкция по публикации пакета — `packaging/aur/README.md`.

## Формат данных

```
v 1500        # средняя скорость, м/с
q 3           # качество (Edit1 в DFM, 0.1..9.99)
profile x0 y0 x1 y1
pick трасса время
...
end
```

`#` — комментарий. Пример: `examples/demo.txt`.

## Производительность

| Что меряли | Время |
|---|---|
| Старт оригинального `03_Fold.exe` | ~370 мс |
| Rust, 15 профилей × 200 пиков | **2.1 мс** |
| Rust, демо | ~0.4 мс |

Алгоритм: `H = V·t/2`, шаг 200 м, карта 8000×4000 м, веса 0.4/0.6, радиус 2000 м — константы вытащены из распакованного бинарника.

## Структура

- `src/model.rs`, `src/velocity.rs`, `src/grid.rs` — ядро;
- `src/io.rs` — парсер и PGM-вывод;
- `src/gui.rs` — egui-клон формы;
- `android-rs/` — JNI-мост на Rust;
- `android/` — Gradle/Kotlin приложение;
- `.github/workflows/` — CI и релизы;
- `packaging/aur/` — PKGBUILD;
- `analysis/` — скрипты дампа, DFM-парсер, дизассемблер и отчёты.

## Оговорка

Нелинейный фильтр оригинала (`0x466250` / `0x466980`) восстановлен приближённо по константам и FPU-коду. Геометрия, единицы и интерфейс сохранены; при эталонных картах корректируется весовая функция в `src/grid.rs`.

Оригинал — забытый эксперимент 2007 года: **лицензий и обещаний нет**.
